# 实现说明

## 请求与登录上下文

验证码存储在 Redis String 中，登录令牌对应的用户信息存储在 Hash 中。
刷新拦截器读取请求头 `authorization`，恢复当前线程的用户上下文并续期；登录拦截器校验受保护接口；请求结束后清理 ThreadLocal。

## 店铺缓存

查询采用缓存优先、数据库回源、写回缓存的流程。不存在的店铺写入短 TTL 空值。
更新店铺后立即删除缓存，并在 500ms 后安排第二次失效。延迟任务位于进程内，没有持久化重试机制，因此只降低缓存不一致风险，不保证强一致性。

## 秒杀与订单

Lua 原子检查库存与购买资格并完成 Redis 预占；MySQL 使用 `stock > 0` 条件更新扣减库存。
订单创建后发送延迟检查消息；支付接口先写入 Redis 标记并投递支付结果，消费者更新订单状态。
超时消费者只处理未支付订单，遇到支付标记则重新延迟检查，否则关闭订单并回补库存。

目前支付与关单在事务方法结束前释放 Redis 锁，订单更新未附带旧状态条件，仍有并发窗口。
Redis 预占、MySQL 事务和消息发送也未组成可靠的跨系统事务；后续应完善事务提交后的处理、条件状态更新以及消息补偿。

## 社交功能边界

关注关系写入数据库和 Redis Set，共同关注使用集合交集。
发帖、热门列表、个人列表和基础点赞已有接口；粉丝收件箱写入与关注动态读取尚未实现。
部分前端详情和关注动态调用仍缺少后端接口，不能将页面存在等同于业务完整。
